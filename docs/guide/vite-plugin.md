# Vite Plugin

The plugin scans a directory for parsers, registers everything it exports and declares the
names it found. A parser you drop in the folder is then available by name, with the type it
was written with.

::: code-group

```ts [vite.config.ts]
import { defineConfig } from 'vite'
import { usewagen } from 'usewagen/vite'

export default defineConfig({
  plugins: [usewagen({ dirs: 'src/parsers' })],
})
```

```ts [main.ts]
import { createWagen } from 'usewagen'
import { parsers } from 'virtual:usewagen/parsers'

const wagen = createWagen({ parsers })
```

:::

```ts
const slug = useRouteState({ key: 'slug', parser: { name: 'parseAsSlug' } })
```

## Types

Two declarations are in play here, and they answer different questions.

`usewagen/client` ships with the package and never changes. It says that
`virtual:usewagen/parsers` exists, which is what lets the import compile at all, the same
way `vite/client` declares the modules Vite adds.

`usewagen.d.ts` is written into your project by the plugin and changes with your parser
folder. It says which parsers you have and what each one returns, which is what turns
`{ name: 'parseAsSlug' }` from an unknown name into a valid parser with a type behind it.

You never add both, because the generated file references the shipped one on its first line.

<!-- prettier-ignore -->
```ts [usewagen.d.ts]
// Auto-generated by usewagen/vite — do not edit
/// <reference types="usewagen/client" />
export {}

declare module 'usewagen' {
  interface CustomParsers {
    parseAsSlug: typeof import('./src/parsers/slug')['parseAsSlug']
  }
}
```

What the generated file does need is for TypeScript to see it. A `tsconfig.json` without an
`include` picks it up already. With one, add it.

```json [tsconfig.json]
{
  "include": ["src", "usewagen.d.ts"]
}
```

If you keep generated types in a folder, point `dts` there and include the path you chose
instead.

## Without the generated file

With `dts: false` nothing is written, and the shipped declaration is the one you bring in
yourself. Either from a declaration file of your own,

```ts [env.d.ts]
/// <reference types="usewagen/client" />
```

or from your tsconfig, next to the other global types.

```json [tsconfig.json]
{
  "compilerOptions": {
    "types": ["vite/client", "usewagen/client"]
  }
}
```

Both give you `virtual:usewagen/parsers`, and the parsers still resolve by name while the
app runs. What you lose is the second question: TypeScript only knows the built-in names, so
a name of your own is an error rather than a typed parser.

## Options

### dirs

- **Type** `string | string[]`
- **Default** `'src/parsers'`

The folders to scan, resolved from the Vite root. Every parser exported from a file in
there is registered under its export name.

### dts

- **Type** `string | false`
- **Default** `'usewagen.d.ts'`

Where to write the declaration file that teaches TypeScript the parser names. Point it
somewhere else if your types live in a folder, or set it to `false` if you would rather
declare the names yourself.
